为重复的 Agent 请求，准备好本地服务

提前计算共享前缀

通过 /v1/prewarm 或 --system-file 提前处理固定系统提示，减少后续请求对命中前缀的重复计算。预热本身需要时间和内存。

按流量选择并发

共享长前缀的请求可从 --profile agent 开始；共享与独有提示混合时可尝试 --profile mixed。预设是起点，自动模式仍为实验选项。

接入并观察运行状态

提供流式生成、工具调用、JSON Schema 约束输出及模型管理命令。通过 /stats 查看缓存、请求阶段与运行状态；支持范围以文档为准。

已经在用 Ollama？

Terrazzo 的侧重点是单台 Mac 上的共享前缀 Agent 工作流。Ollama 同样具备缓存与并发能力；这里的选择理由是预热、预设和观测的使用流程，而不是“只有我们才有”。

你的需求如何选择
只想下载模型、日常聊天如果 Ollama 已满足需求，目前没有充分理由仅为 Terrazzo 更换工具。
多个 Agent 反复携带长系统提示可以试用显式前缀预热与并发预设，用自己的请求序列评估延迟和内存。
希望复用已有客户端支持 OpenAI 兼容及部分 Ollama 端点；先核对端点、工具调用行为和 MLX 模型格式。
想知道是否一定更快没有普遍更快的结论。缓存状态、并发、量化和配置都会影响结果。

跑起来

shell
# 克隆 + 安装（Apple Silicon，macOS 14+）
git clone https://github.com/louisyeaaah/terrazzo.git
cd terrazzo
python3 -m venv .venv && . .venv/bin/activate
pip install -e . -c constraints.txt

# 拉模型、起服务
terrazzo pull mlx-community/Qwen3-4B-4bit
terrazzo serve --model Qwen3-4B-4bit --port 8080 \
    --profile agent
OpenAI / Ollama API
# OpenAI 兼容
curl localhost:8080/v1/chat/completions \
  -H 'Content-Type: application/json' -d '{
  "model": "terrazzo",
  "messages": [{"role":"user","content":"解释一下 KV cache。"}],
  "max_tokens": 128
}'

# 预注册共享前缀（或启动时 --system-file）
printf '%s\n' 'You are a helpful assistant.' > system.txt
terrazzo prewarm --base http://127.0.0.1:8080 \
    --system-file system.txt

# Ollama 原生风格
curl localhost:8080/api/chat -d '{
  "model":"terrazzo","stream":false,
  "messages":[{"role":"user","content":"你好"}]
}'

当前范围与项目来源

单机、单个已加载模型

面向 Apple Silicon 与 MLX 模型，提供鉴权、超时、取消和故障处理机制。没有 embeddings 或分布式服务能力；真实 GPU 故障恢复仍需进一步验证。

建立在开源生态之上

计算与批处理基于 MLX / mlx-lm。调度设计借鉴 DeepInfer；逻辑块管理不等同于主执行路径的物理 paged attention。
