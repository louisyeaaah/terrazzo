Local inference for your agents.
On your Mac.

Terrazzo runs on MLX, with shared-prefix prewarming, selectable concurrency presets, and OpenAI-compatible and selected Ollama API endpoints for local agent workflows.

Prepare your local server for repeated agent requests

Prewarm shared prefixes

Prepare a fixed system prompt with /v1/prewarm or --system-file. Later requests can reuse matching prefixes. Prewarming itself takes time and memory.

Choose a concurrency preset

Start with --profile agent for shared-prefix traffic or try --profile mixed for shared and unique prompts. Presets are starting points; automatic selection remains experimental.

Connect and inspect

Use streaming, tool calling, JSON Schema constrained output, and model-management commands. Inspect cache and request state through /stats; consult the docs for supported behavior.

Already using Ollama?

Terrazzo focuses on shared-prefix agent workflows on one Mac. Ollama also supports caching and concurrency; the distinction here is the workflow around explicit prewarming, presets, and observability.

Decide based on your workflow
Your use caseWhat to consider
Downloading models and everyday chatIf Ollama already meets your needs, there is no established reason to switch just for Terrazzo.
Several agents repeatedly send long system promptsTry explicit prefix prewarming and concurrency presets, then measure latency and memory on your own request sequence.
Reusing an existing clientOpenAI-compatible and selected Ollama endpoints are available. Check endpoints, tool behavior, and the MLX model format before switching.
Expecting a guaranteed speedupThere is no universal speedup claim. Cache state, concurrency, quantization, and configuration all affect results.

Models use Hugging Face MLX snapshots. Ollama registry / GGUF support is not included, and API coverage is partial. Check API coverage and limitations ↗

Run it

shell
# clone + install (Apple Silicon, macOS 14+)
git clone https://github.com/louisyeaaah/terrazzo.git
cd terrazzo
python3 -m venv .venv && . .venv/bin/activate
pip install -e . -c constraints.txt

# pull a model, start the server
terrazzo pull mlx-community/Qwen3-4B-4bit
terrazzo serve --model Qwen3-4B-4bit --port 8080 \
    --profile agent
openai / ollama api
# OpenAI-compatible
curl localhost:8080/v1/chat/completions \
  -H 'Content-Type: application/json' -d '{
  "model": "terrazzo",
  "messages": [{"role":"user","content":"Explain KV cache."}],
  "max_tokens": 128
}'

# prewarm a shared prefix (or at startup)
printf '%s\n' 'You are a helpful assistant.' > system.txt
terrazzo prewarm --base http://127.0.0.1:8080 \
    --system-file system.txt

# native Ollama-style
curl localhost:8080/api/chat -d '{
  "model":"terrazzo","stream":false,
  "messages":[{"role":"user","content":"hi"}]
}'

Performance in context

Published comparisons help you choose, but each result describes a specific machine, model, and configuration. Prewarmed request latency is not an engine speedup over an uncached request.

Compare on your own workflow

Scope and foundations

One machine, one loaded model

Built for Apple Silicon and MLX models, with authentication, deadlines, cancellation, and failure handling. Embeddings and distributed serving are not included; recovery from real GPU faults still needs validation.

Built on open source

Compute and batching build on MLX / mlx-lm. Scheduling draws on DeepInfer. Logical block management is not physical paged attention in the main execution path.
