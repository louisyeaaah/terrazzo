Terrazzo ports DeepInfer's paged-KV scheduler to a single Mac, then wraps it in OpenAI- and Ollama-compatible APIs — with pre-registered shared-prefix caching for the long system prompts that real agent traffic has.

Long system prompts & prefix caching

pre-registration is the differentiator

A pre-registered prefix is prefill work done once, before traffic. Cold first-token latency for 2k / 4k / 8k shared prompts:

PromptTerrazzo defaultTerrazzo pre-registeredOllama coldSpeed-up
2k tokens4.37 s0.154 s3.20 s20.8×
4k tokens8.91 s0.242 s6.95 s28.7×
8k tokens19.87 s0.343 s17.61 s51.3×

Warm reuse: Ollama is still faster

When the exact same prompt is reused, Ollama answers in 0.033–0.060 s at 2k–8k versus Terrazzo's 0.081–0.153 s. Terrazzo's advantage is the first request of a new shared prompt, not pure cache hits.

Long-context decode

87.2 tok/s at 1k, 76.3 at 2k, 70.7 at 4k, 57.2 at 8k. Decode on the same 2k/4k/8k prompts with a pre-registered prefix: 82.8 / 74.6 / 57.0 tok/s vs Ollama 45.2 / 43.6 / 38.0.

Where it wins — and where it doesn't

Wins

Agent traffic on one Mac

2.2× Ollama's throughput at 16 concurrent sessions, pre-warmed first token 10–50× faster on 2k–8k shared prompts, and single-stream / 4-session latency better than vLLM-Metal. One process speaks OpenAI and Ollama, with tools, JSON Schema and a model store.

Doesn't

Scale-out throughput and cold prefix reuse

vLLM-Metal beats 16-session throughput (122.1 vs 88.7 tok/s) and TTFT (1.57 vs 2.56 s). Ollama is faster for cold prefill without pre-registration and for pure warm-prefix reuse. No Ollama registry, no GoFF, no embeddings, single machine.

Honest summary: Terrazzo is an agent inference gateway for one Apple Silicon machine, not a drop-in throughput replacement for vLLM at scale. The paged-sharing attempt that would have changed the memory story was measured and lost — the numbers are kept in BENCHMARKS.

What's inside

Paged KV engine

Block manager with ref-counting, continuous batching, round-robin chunked prefill and LCFS preemption.

Prefix caching

Exact shared-prefix snapshots, automatic batch registration, /v1/prewarm and --system-file for zero-prefill first tokens.

OpenAI + Ollama APIs

Chat/completions, streaming, JSON Schema constrained decoding, tools/function calling, NDJSON Ollama endpoints.

Ollama-style CLI

run, pull, list, show, rm, cp, create -f Modelfile, ps, prewarm.

Production hardening

Constant-time auth, optional TLS, rate limits, bounded concurrency, request deadlines, worker hang watchdog.

Boring reliability

240 core tests + 31 kernel tests, MLX-free CI job, pinned MLX versions, validated runtime-patch contract.

Run it

shell
# clone + install (Apple Silicon, macOS 14+)
git clone https://github.com/louisyeaaah/terrazzo.git
cd terrazzo
python3 -m venv .venv && . .venv/bin/activate
pip install -e . -c constraints.txt

# pull a model, start the server
terrazzo pull mlx-community/Qwen3-4B-4bit
terrazzo serve --model Qwen3-4B-4bit --port 8080 \
    --profile agent --system-file system.txt
openai / ollama api
# OpenAI-compatible
curl localhost:8080/v1/chat/completions \
  -H 'Content-Type: application/json' -d '{
  "model": "terrazzo",
  "messages": [{"role":"user","content":"Explain KV cache."}],
  "max_tokens": 128
}'

# prewarm a shared prefix (or at startup)
terrazzo prewarm --base http://127.0.0.1:8080 \
    --system-file system.txt

# native Ollama-style
curl localhost:8080/api/chat -d '{
  "model":"terrazzo","stream":false,
  "messages":[{"role":"user","content":"hi"}]
}'
